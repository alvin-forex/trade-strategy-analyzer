## 1. 問題定義

對**每一層**（L1、L2、L3…），測試：**不即時入場，而是等價格朝某方向再走 X pips 才入場**，X 由 0 掃到 50。找出每層「最適合的延遲距離」——以勝率、賠率、期望 pips 三個指標衡量。

「延遲」＝價格距離，與時間無關；同一筆交易可能幾分鐘就到 X pips，也可能幾小時都不到（那就視為不觸發）。

---

## 2. 兩個模式（按手上資料決定用哪個）

### 模式 A — 近似（現有 33 欄即可做，先用這個）
只用 `Max Pips`（MFE）與 `Max Loss Pips`（MAE），不需價格路徑。

對每筆交易、每個 X（pips）：

- **逆勢延遲**（等價格先走差 X pips 才入場）：需要 `Max Loss Pips ≥ X`，否則不觸發。
- 觸發後：
  - 剩餘有利幅度 ≈ `Max Pips + X`（因為入場價更差，同樣的高點多賺 X）
  - 剩餘不利幅度 ≈ `Max Loss Pips − X`
- 判定：若原交易獲勝且 `Max Pips + X ≥ TP 距離` → 記勝；若原交易虧損 → 需標「先到 TP 或先到 SL 未知」，用**保守假設**（先到 SL）計。

> 必須在報告首段寫明「本結果為近似，先後次序未驗證」，不得當精確回測。

### 模式 B — 精確（有 statement＋本機 M1 才做）
用每筆開倉時刻與方向，在 M1 路徑上找「第一次觸及 X pips」的時刻，由該點重新入場，之後完全照原 SL/TP 走，逐步模擬至出場。這是真值，但需要 `Open Time／Open Price／Lots／Symbol／Type／SL／TP` 齊全。

**建議**：先用模式 A 出第一版矩陣（今日可做），同時向 OC／老闆取得 statement 後轉模式 B 校準。

## 4. 每格輸出（矩陣）

| 指標 | 定義 |
|---|---|
| 觸發率 | 該層在 X 下有多少比例的交易會觸發（`MAE ≥ X` 的比例） |
| 勝率 | 觸發樣本中獲勝比例 |
| 賠率 | 平均獲勝 pips ÷ 平均虧損 pips |
| 期望（pips/筆） | 勝率×平均勝 −（1−勝率）×平均虧 |
| 樣本數 | 少於 30 標灰，不作結論 |
