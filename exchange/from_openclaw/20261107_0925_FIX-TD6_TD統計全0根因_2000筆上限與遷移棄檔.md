## 二、根因（三層，全部可證）

### 根因 1（致命，令同步永久停擺）— `SyncTradesFromHistory()` 由最舊掃 + 2000 硬上限

```mql4
int histTotal = OrdersHistoryTotal();
if(histTotal > 2000) histTotal = 2000;   // line 1861
for(int i = 0; i < histTotal; i++)       // index 0 = 最舊
{
   if(OrderCloseTime() < since) continue;  // since = TimeCurrent() - SnapHours(72)*3600
```

- MT4 history 索引 **0 = 最舊、越大越新**。此帳戶 10 月中開始密交易（單日 300～1,800 張），歷史在 **10-21 前後突破 2000 張**。
- 之後 `index 1999` 永遠停留在凍結日，所有新成交落在 `index >= 2000`，**永遠掃唔到**；再加 72 小時窗口過濾，`newCount` 永遠 0 → `SaveTrades()` 只重寫舊陣列 → 靜默停擺。
- 時間吻合：log 最後一次成功 SYNC 係 10-21 17:36，正好係破 2000 嘅時點。

### 根因 2 — `SnapHours = 72` 令同步窗口只有 3 日

即使掃描次序修正，W/M 視圖仍要靠 per-account CSV 長期累積。窗口只 3 日唔算 bug，但**遷移／重建檔案時必須保留舊數據**，否則一遷移就清零。

### 根因 3（今早引爆）— `MigrateLegacyTDFiles()` 只改名、不搬數據

v1.53 首次啟動時：
1. `MigrateLegacyTDFiles()` 把 `TD_trades.csv`（872 張）改名 `TD_trades.csv.legacy` → 唔會再被讀；
2. 新 `TD_28152862_trades.csv` 不存在 → `LoadTrades()` 讀 0 張；
3. `OnInit` 的 `SyncTradesFromHistory()` 又被根因 1 卡死 → 0 張；
4. 之後每 5 分鐘 sync 一次，仍然 0 → `TD_28152862_summary.csv` 只寫表頭。
→ H/D/W/M 全部 0。

### 「部分欄有正確值」的解釋

| 有值 | 無值（全 0） |
|---|---|
| Balance / Equity / Margin / FreeMargin（即時 `AccountXxx()`） | Trades / Buy / Sell / WR% / Gain$ / Gain% / WPips / Lot / TotalLot / PF |
| 持倉列表、DDGuard SYMBOL 列、浮虧（`OrdersTotal()` 即時持倉） | MaxDD$ / MaxDD% / AvgP&L / Best / Worst（靠 `t_` 陣列） |

一句：**即時帳戶數據正常，靠成交陣列的統計全 0** — 同截圖完全一致。
