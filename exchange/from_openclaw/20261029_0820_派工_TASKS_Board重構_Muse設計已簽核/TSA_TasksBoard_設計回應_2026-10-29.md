## 二、卡片內表格 responsive：三方案實測 → **揀 C（關鍵欄置頂）**

三個方案用**同一份真實數據**（TASKS.md 進行中 #1/#2，240 字狀態格）建 prototype，390px 量度：

| 方案 | 做法 | 卡高（同 2 列） | 任務欄寬 | 任務欄行數／每行字數 | 狀態欄每行字數 | 標籤數 | 判斷 |
|---|---|---|---|---|---|---|---|
| **A 欄收窄** | 保持 4 欄，`table-layout:fixed` + 百分比 | **375px** | **67px** | **8 行 / 4 字** | 20 字 | 0 | ❌ 否決 |
| **B 全堆疊** | 每欄獨立一行，全部出標籤 | 550px | 336px | 1 行 / 34 字 | 34 字 | 6 | ⚠️ 可行但太高 |
| **C 關鍵欄置頂** | 任務名全寬第一行；次要欄逐行帶標籤 | **430px** | 336px | 1 行 / 34 字 | 34 字 | 4 | ✅ **採用** |

### 2.1 為何否決 A（呢個係現版正在做嘅事，只係做得更極端）

A 方案 390px 下「任務」欄 67px＝**每行 4 個字**，34 字標題變 8 行；320px 更差（53px＝3 字/行、11 行）。A 本質上係「接受欄變窄」，但中文表格嘅最小可讀欄寬唔係算術平均——「任務」欄要 ≥180px 先有 12 字/行。只要 4 欄並排，390px 減 padding 淨 306px，分唔到。**A 係結構性死路，唔係調參問題。**

### 2.2 為何揀 C 而非 B

B 同 C 嘅任務欄表現一樣（1 行 34 字）。差別在**垂直成本**：
- B 每列 3 個標籤（任務／狀態／#·ETA），2 列 = 550px。
- C 每列 2 個標籤（狀態／ETA），2 列 = 430px。**省 120px（22%）**。
- B 仲有一個副作用：標籤滿天飛，視覺噪音大過資訊量。

C 再減一刀（實測）：連「任務」標籤都唔出 → 每列再省 22px，總高 2,422px vs 2,531px。理由：一段文字排喺序號下面、用 15px/600，讀者自然知道係標題；出「任務」標籤係告訴人一件佢已經知道嘅事。

### 2.3 C 方案嘅完整欄行為規格（ZCODE 照抄）

**桌面（≥1200px）：4 欄 grid，唔用 `<table>`**

| 欄 | 寬度 | 內容規則 | 溢出處理 |
|---|---|---|---|
| `#` | 26px 固定 | 序號，12px，`tabular-nums`，`--neutral` | 不出現（1–2 位數） |
| 任務 | `minmax(0,205px)` | 15px/600，`line-height:1.5` | `overflow-wrap:anywhere`；實測最長標題 2 行 |
| 狀態／證據 | `minmax(0,1fr)`（1280 實測 330px；1024 時 224px） | 14px/400，粗體結論先行；>70 字轉 `<details>` | `overflow-wrap:anywhere`；摺疊後 ≤3 行可見 |
| ETA／證據 | 82px 固定 | chip 12px，可換行 | `white-space:normal`，唔准 ellipsis 截斷 |

實測欄寬對照：1280 = `26 / 205 / 330 / 82`；1024 = `24 / 180 / 224 / 76`；768（平板過渡）= `24 / 180 / 388 / 76`。

**手機（<768px）：單欄堆疊，任務欄置頂**

| 順序 | 內容 | 樣式 | 備註 |
|---|---|---|---|
| 1 | `#` 序號 | 12px `--neutral` | 唔出標籤 |
| 2 | 任務名 | 15px/600，全寬 | **唔出標籤**（實測省 45px/列） |
| 3 | 狀態 | 14px/400，左 2px 豎線＋`狀態` 12px 標籤 | 豎線色＝卡片狀態色 |
| 4 | ETA | chip 12.5px＋`ETA` 12px 標籤 | |

**完成卡（2 欄：任務／證據）**：桌面 `minmax(0,1.15fr) / minmax(0,1fr)`；手機單欄，任務 15px/600 在上、證據 13.5px/`--t2` 在下，證據出「證據」標籤。

### 2.4 三個必須遵守嘅細節（我踩過坑）

1. **`grid-template-columns` 用 `minmax(0, …)`，唔用 `1fr`**。`1fr` 嘅 min-width 係 `auto`，遇到長英數 token（`_xludf.ImportCSV`、`tsa_20261028.db.gz`）會把欄撐爆——呢個就係 10-27 卡片修過嘅 `c30ed0b6` 溢出 bug 同類。全部欄要 `min-width:0`。
2. **中段寬（768–1199px）一定要獨立斷點**。我第一版只寫 768 同 1200 兩個斷點，結果 1024px 時任務欄 205px + 狀態欄被壓到 224px，行高 99px、中文字尾撞欄（`c-task` 溢出 6px）。加 `@media (min-width:768px) and (max-width:1199px){ .row:not(.row-2){ 24px / 180px / 1fr / 76px } }` 後歸零。**注意 `:not(.row-2)`**——唔加嘅話完成卡嘅兩欄版面會被 4 欄規則覆蓋，逐格變 24px 寬（我實測到呢個 bug）。
3. **中文標點會凸出 3px**。CJK 避頭尾規則令 `）`、`，` 掛喺行尾外側。390px 下 `.t` 有 1 個元素 `scrollWidth - clientWidth = 3px`，但該 3px 完全落喺卡片 `padding-right` 內（實測 `textRight 353 < cardContentRight 364`），**冇視覺截斷、冇頁面橫捲**。驗收門檻要容許「頁面級 0 溢出；元素級 ≤4px 且必須落在 padding 內」，否則會追一個假 bug。

## 六、生成器分工＋ZCODE 逐項 checklist

### 6.1 Lane 分界（一條線畫清）

```
TASKS.md（內容・狀態・數字・時間戳）
        │
        │  ← DATA LANE：OpenClaw（main）
        │     管：寫咩、section 次序、狀態歸屬、最後更新時間
        ▼
scripts/tasks_board_gen.py（解析 ＋ 渲染 ＋ inline CSS）
        │
        │  ← CODE LANE：ZCODE
        │     管：HTML 結構、CSS、responsive 斷點、可及性、加密流程
        ▼
docs/admin/tasks_board.html（staticrypt 密文，owner 層）
```

**分工鐵律**
- **OpenClaw 唔准改** `tasks_board_gen.py` 嘅 CSS／DOM 結構；只可以經 TASKS.md 內容影響頁面。
- **ZCODE 唔准改** TASKS.md 嘅任務描述文字；發現內容問題（如 §0.3 兩個缺陷）→ 回報 main lane，唔好自己執。
- **解析契約（版本化）**，任何一邊改都要通知另一邊：
  - `## <emoji> <標題>` — 一個 section 一張卡；**emoji 係狀態唯一來源**（🔄/📅/✅/⏸/👀）。
  - 首個 `|` 表格 — 4 欄＝`#|任務|狀態|ETA`；2 欄＝`任務|證據`。
  - `- ` ／ `1. ` 列表 — 無表格時用；有序列表保留原編號。
  - `> ` 開頭（首段）— 頁面說明；`> 最後更新：…` 抽去 meta 列。
  - 新增狀態時：**先** ZCODE 加 badge 樣式，**後** OpenClaw 落新 emoji；否則新 section 會 fallback 成「其他」。
