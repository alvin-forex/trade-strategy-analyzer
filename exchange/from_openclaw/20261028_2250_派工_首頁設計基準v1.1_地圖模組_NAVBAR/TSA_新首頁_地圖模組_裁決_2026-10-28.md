## ① 世界地圖做首頁 hero — 適合與否

### 裁決：**有條件接受。定位為 P1「事件地理層」，加模組，唔取代任何模組。**

**accept 嘅理由**（老闆呢個直覺係對嘅）：
- TSA 而家 12 個模組全部答「幾多」同「幾時」，**冇一個答 WHERE**。老闆睇 FOMC 會問「係邊個國家／邊隻貨幣」，地圖補嘅係真空白，唔係裝飾。
- 外匯事件本質地理化（USD/FOMC、EUR/ECB、JPY/BoJ…），地圖嘅認知負荷低過列表——呢個係地圖唯一贏列表嘅場景。

**reject「hero」嘅理由**（數據講話）：
- **版面效率太低**：8 大貨幣國事件點只有 3–6 個，但 1280×400 嘅世界地圖有 90% 面積係海洋／無事件國家。用 400px 高去顯示 5 個點，資訊密度約 3%。呢個唔係 hero，係壁紙。
- **會推走決策模組**：v1.0 桌面首屏（1280×~800 可視）＝KPI 120px + 熱力圖 + 排名。加一個 400px hero，排名表即刻跌出首屏。手機更嚴重——v1.0 手機首屏只放兩個模組，地圖一上首屏就推走 CCY 熱力圖。
- **違反 v1.0 「克制」原則**：hero 地圖必然要配大留白／大字／強動效先撐得起，同「少許特效」直接衝突。

### 落地規格

| 項目 | 裁決 |
|---|---|
| 位置 | 桌面：KPI 頂欄之下，**橫跨全寬**（跨越現有左右兩欄） |

| 取代 | **唔取代任何模組**。12 個模組全保留 |

| 手機 | **唔放**（見 ④） |

## ② 閃動處理 — 連續 BLINGBLING 否決

### 裁決：**否決「連續 BLINGBLING」。採用「慢呼吸光暈（4s 週期）」＋「新事件單次 pulse」。**

### 2.1 連續閃為何唔得（技術上係違規，唔止係「唔靚」）

| 方案 | 頻率 | WCAG 2.3.1 三閃爍門檻（每秒 >3 次＝紅色警戒） | 裁決 |
|---|---|---|---|
| 連續 BLING（例如 200ms 一次） | **5 Hz** | **直接違規**，且有光敏性癲癇風險 | **禁止** |
| 柔光 pulse 300ms 一次 | **3.3 Hz** | **踩正紅線**（>3 次／秒） | **禁止** |
| 慢呼吸光暈 4s 週期 | **0.25 Hz** | 遠低於門檻 | **採用** |

補兩點實務考慮：
- 300ms 一次 = 每分鐘 200 次閃。8 個國家同時閃 = 每分鐘 1600 次視覺變化的噪音場，**老闆睇盤時會直接想熄咗個網頁**。呢個唔係「高級科技感」，係賭場老虎機。
- v1.0 第三節寫明「**明確禁止任何 loop 動畫**」。4s 呼吸光暈係唯一例外，條件見 2.3——我而家正式修訂 v1.0 該條。

### 2.2 具體動效規格（三層，由弱到強）

| 層 | 效果 | 時長／週期 | 觸發 | 範圍 |
|---|---|---|---|---|
| **L1 常駐底** | 事件國填色 sem/danger 或 sem/warn @ **12% alpha** ＋ 1px 實線環 | 靜態 | 有事件就顯示 | 全部有事件國家 |
| **L2 呼吸光暈** | 外暈 0→8px、alpha 0→22%→0，`opacity/box-shadow` 只用 transform+opacity 等效寫法 | **4s 週期**（ease-in-out） | 常駐（只限頂 3 個） | **同時最多 3 個點**（見 2.3） |
| **L3 新事件 pulse** | 光暈**單次**放大 1→1.6 倍並淡出，**播 2 次後停止** | 每次 400ms，總 1.6s，**只播一次唔 loop** | 新事件進入數據（`generated_at` 變更後首次 render） | 該事件國家 |

L3 就係「BLINGBLING 感」嘅唯一出口：**有一次搶眼，但唔會持續騷擾**。老闆要嘅「閃」係「提示我留意」，唔係「一直閃」。

### 2.3 WCAG 2.2.2 Pause, Stop, Hide — 官方立場

**立場：地圖任何自動動畫都必須可停。呢個係硬性驗收項，唔係 nice-to-have。**

| 要求 | 落地 |
|---|---|
| **Pause/Stop** | 地圖右上角常駐 **⏸／▶ 動效開關**（24×24px，觸控熱區 ≥44×44px）。狀態存 `localStorage`，跨頁保留 |
| **Hide** | 關閉後：L2 呼吸同 L3 pulse **全部停止**，只保留 L1 靜態填色＋實線環。**資訊零流失**（靜止態仍然睇得出邊個國家 HIGH/MED） |
| **5 秒規則** | 呼吸光暈屬「5 秒以上自動開始並持續」嘅內容 → 必須有 pause 機制 → 已提供 |
| **reduced-motion** | `@media (prefers-reduced-motion: reduce)` → 自動等同關閉：無呼吸、無 pulse，只剩 L1 靜態 |
| **同時數量上限** | 呼吸點**最多 3 個**。第 4 個起只出 L1 靜態環 + 排序 badge，唔准一齊呼吸（防「滿屏燈膽」） |
| **效能** | 動畫只用 `opacity` / `transform`，**唔准**動 `box-shadow`、`filter: blur()`（手機 GPU 殺手，會跌幀）。光暈用預渲染 radial-gradient 圖層做 opacity 過場 |

### 2.4 色階 ＋ 雙編碼（色盲安全）

色值全部用 v1.0 tokens，我實算過對比（底色 L0 `#0F1520`／L1 `#161E2E`／L2 `#1C2638`）：

| 級別 | 色 token | 色值 | 對 L0 | 對 L1 | 對 L2 | 環／暈 | **形狀編碼** | **文字編碼** |
|---|---|---|---|---|---|---|---|---|
| **HIGH** | sem/danger | `#FF6B6B` | **6.59:1** | **6.01:1** | **5.47:1** | 2px 實線環 ＋ 紅暈 22% | **▲ 實心三角 ＋ 雙圈** | `HIGH` 字樣（必出） |
| **MED** | sem/warn | `#FFB454` | **10.37:1** | **9.46:1** | **8.61:1** | 1.5px 實線環 ＋ 黃暈 14% | **◆ 菱形 ＋ 單圈** | `MED` 字樣（必出） |
| 無事件 | neutral | `#8B95A5` | 6.04:1 | 5.51:1 | 5.02:1 | 無環 | 小圓點 | 唔標 |

**三重編碼鐵律（缺一即退件）**：
1. **色**（紅／黃／灰）— 只用嚟加速掃視，唔可以係唯一資訊載體
2. **形狀**（▲ ／ ◆ ／ •）— 色盲／灰階列印都分得出
3. **文字**（`HIGH` / `MED`）— 地圖上每個事件點旁必帶 12px 標籤，`#E6EDF5` 或語義色，對 L1 ≥4.5:1

三項全部合格。注意：地圖上嘅 **12px 標籤唔准用 txt/tertiary `#7A8698`**（對 L2 只有 **4.11:1**，已實測不合格，同 v1.0 第二節限制一致）。

## ④ 手機 390px — 地圖唔放首屏

### 裁決：**地圖唔放首屏，亦唔放二屏。改用「事件國家 strip」。**

**否決手機地圖嘅硬理由**：
- **390px 寬嘅世界地圖物理上睇唔到歐洲**：EUR / GBP / CHF 三國喺 390px 地圖上嘅水平間距約 8–14px，事件點直徑（含環）就係 ~18px，**必然疊埋**。疊埋嘅地圖比冇地圖更差——老闆會以為倫敦有事其實係法蘭克福。
- 要分清就要拉高到 ~240px，佔 390px 首屏 1/3，直接推走 CCY 熱力圖。
- v1.0 手機首屏裁決（HIGH 倒數 + CCY 熱力圖）係基於「手機＝睇盤場景」，唔可以為新模組讓位。

### 替代方案：事件國家 strip

```
┌────────────────────────────────┐
│ 事件帶（44px，橫向 scroll）      │
│ ┌──────┐ ┌──────┐ ┌──────┐    │
│ │▲USD  │ │◆JPY  │ │▲EUR  │ →  │
│ │02:00 │ │11:30 │ │15:00 │    │
│ │FOMC  │ │BoJ   │ │ECB   │    │
│ └──────┘ └──────┘ └──────┘    │
└────────────────────────────────┘
```

| 規格 | 值 |
|---|---|
| 高度 | **44px**（含 padding），佔位極細 |
| 位置 | 手機首屏**最頂**（KPI 壓縮行之下、HIGH 倒數之上），因為佢係「一覽」層 |
| chip 尺寸 | 高 44px（觸控合格）、寬 auto（約 84–96px），間距 8px |
| chip 內容 | 形狀 icon ＋ 3 字母代碼 ＋ HKT 時間 ＋ 事件簡名（≤6 字，超出 ellipsis） |
| 排序 | HIGH 先，同級按時間升冪 |
| 上限 | 最多 8 個 chip，超出橫向 scroll，**唔准** wrap 成兩行 |
| 點擊 | 開同 ③ 一樣嘅 bottom sheet |
| 溢出 | `overflow-x:auto`、`scroll-snap-type:x proximity`、`-webkit-overflow-scrolling:touch`；**零橫向頁面溢出**（container 要 `max-width:100vw` 已由 v1.0 覆蓋） |

**⚠️ 一個實際伏位要工程知**：**唔准用 emoji 國旗**（🇺🇸）。Windows 唔支援旗幟 emoji（會渲染成 `US` 兩個字母方塊），而老闆用 Windows。所以 strip 同 popover 一律用 **3 字母貨幣代碼徽章**（`USD` / `JPY`）＋ 語義色，旗幟可以做純裝飾 fallback，但**唔可以係唯一識別**。

**手機版地圖去邊**：唔出。如果老闆堅持要，只准放**頁尾可摺疊區**（`<details>`，default 收起）＋ lazy load，並接受 ④ 嘅「疊點」風險。我建議唔做——strip 已經 100% 覆蓋「WHERE + WHEN」。

## ⑤ SVG 簡化版 vs 全世界 — bundle 決策

### 裁決：**8 大貨幣國簡化版（~40KB）。全世界版（~150KB）否決。**

| 指標 | 8 國簡化版 | 全世界版（150KB） | 判 |
|---|---|---|---|
| 資訊覆蓋 | 8/8 個貨幣國 = **100% 有用資訊** | 8/8 個貨幣國 ＋ 185 個無關國家 | 8 國贏 |
| 佔 300KB 預算 | **13%** | **50%** | 8 國贏 |
| 剩餘預算 | ~260KB 畀 CSS/JS/HTML/數據 | ~150KB，隨時爆 | 8 國贏 |
| gzip 後 | 估 ~18–25KB（大面積色塊壓縮率高） | 估 ~55–70KB | 8 國贏 |
| 手機 parse/render | path 數少，LCP 友善 | path 多，低階 Android 會掉幀 | 8 國贏 |
| 視覺 | 8 國＋海洋，乾淨 | 全世界，但 90% 面積係噪音 | 8 國贏 |

**理由核心**：呢個地圖嘅**任務**係「8 隻貨幣邊隻有事件」，唔係「展示世界地理」。150KB 買多 185 個唔會有事嘅國家，係純粹嘅裝飾成本。**設計上永遠唔應該為咗「似地圖」而犧牲「係資訊」**。

技術約束（唔寫 code，但規格要落）：
- 用 `viewBox` + `preserveAspectRatio="xMidYMid meet"`，響應式縮放，唔出多套尺寸
- path 簡化容差：目標尺寸下 ≤0.5px 誤差（Douglas–Peucker）
- **inline 入 HTML**，唔另開 request（多一個 request 嘅 RTT 貴過 gzip 後嘅 20KB）
- 配色：無事件國家 `bg/L2` 填 + `line/hairline` 1px 描邊；海洋 `bg/L0`；有事件國家 `sem` 色 @12%

### Lazy load 可唔可以唔計入首屏預算？

**裁決：要分「首屏」同「非首屏」，唔准用 lazy 繞預算。**

| 情境 | 計唔計入 300KB？ | 規矩 |
|---|---|---|
| 資產**在首屏可見區**（above the fold） | **計，一定要計** | **唔准** lazy load。用 lazy 只係把成本推遲到 LCP 後，會造成「地圖位一直空白」＋ **CLS**（排版位移），Lighthouse mobile ≥85 直接受累 |
| 資產**喺非首屏**（`<details>` 摺疊、bottom sheet 內、頁尾） | **唔計入首屏預算，但計入 total page weight** | 准 lazy，但必須：(a) 用 `loading="lazy"` 或 IntersectionObserver；(b) **預留 `width`/`height` 或 `aspect-ratio`** 防 CLS；(c) 喺 Lighthouse 報告度仍然要交代 total |
| 用 lazy load 掩飾「首屏資產過大」 | **禁止** | 呢個係作弊，我會喺簽核時打回頭 |

> 所以答案係：**我唔需要靠 lazy load 找數**——8 國版 40KB 本身就落得入預算（13%）。lazy 只係畀手機版可摺疊地圖（如果真做）同 popover 內嘅小圖示用。

## ⑥ 新增模組：數據契約（沿用 v1.0 第六節格式）

**紅線不變**：全部 pre-generated JSON，首頁唔准 client fetch SQLite；時間一律 HKT ISO8601。

| 模組 | 檔案 | 欄位（名:型別） | 更新 |
|---|---|---|---|
| 世界地圖 | `home/map_events.json` | `currency: string(3)`、`country: string(2, ISO3166)`、`impact: enum[HIGH,MED]`、`event: string`、`time_hkt: string(ISO8601)`、`source: enum[forexfactory,tradingview]`、`event_count_24h: int`、`max_impact: enum[HIGH,MED,none]`、`generated_at: string` | 每小時（同 `news_high.json` 同一 generator，**必須同源**） |
| 手機事件 strip | 同上（複用） | 前端 filter：未來 24h、按 impact＋時間排序、取前 8 | 同上 |

**兩條契約鐵律**：
1. **`map_events.json` 同 `news_high.json` 必須由同一支 generator、同一時間點產出**。唔准兩支程式各自算——老闆喺地圖見到 USD HIGH 但右欄倒數冇，就會質疑全部數據（同 v1.0 第七節第 7 條同一原則）。
2. `country` 用 ISO 3166-1 alpha-2（`US`/`GB`/`JP`/`EU`…），前端靠佢 mapping 去 SVG path id；**唔准**靠中文國名匹配。EU 唔係國家但外匯必需，用 `EU` 作 pseudo-code 落契約。
