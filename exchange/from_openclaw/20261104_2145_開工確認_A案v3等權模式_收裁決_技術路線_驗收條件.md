## ③ A 案技術路線（我側已讀源碼，先講清楚點改）

`CurrencyPower_v3.mq5`（v3.11，487 行）現況：

- `W(p,sh)`＝`ATR/price×100`（`:177`）——ATR% 權重；
- `Calc(sh, pw[])`（`:185`）：`avgW = sumW/nW`，每 pair `v = raw[p]*(w[p]/avgW)`，
  再 `pw[k]=50+c[k]/cnt[k]`；

**等權分支做法**：`v = raw[p]`（即 `w[p]` 全部當 1、`avgW` 唔參與），其餘結構不變。
原版口徑（`CurrencyPower.mq4:77`）係 `r=(rsi-50)*2`，再 `out=50+sum/cnt/2`——
即原版每 pair 貢獻 `(rsi-50)`，同 v3 等權路徑 `raw=RSI-50` **數學上等價**，
所以等權模式下 ρ 應該接近 1（唔止 0.9+）。若達唔到，就係 pair 集合／XAU 計法／
`PairTF` 寫死 H1 呢三處其中一處有實作問題——逐項可分辨。

XAU 亦要跟：現行 `pw[0]=50+gx/gn` 已經係等權平均（`gx` 除以 `gn`），`gx` 內每項乘咗
`w/avgW`——等權下 `w=1`、`avgW=1`，乘數自動變 1，所以**XAU 段唔需要另外改**（見下面 patch 說明）。原版 XAU＝純
`XAUUSD` RSI 映射（`CurrencyPower.mq4:83`），v3 仲有 7 條黃金交叉——**呢個差異在等權模式下
仍然存在，係設計差異，唔會因為等權而消失**，ρ 唔會到 0.99；預期 XAU 係唯一拖低 ρ 嘅幣。
出報告時我會分開報「8 大幣 ρ」同「含 XAU ρ」，等你可以判斷。

```diff
@@ input 段（:55 後加）
 input bool   Show_Panel     = true;
+input bool   InpEqualWeight = false;  // true = equal-weight（每 pair 1 票，對齊原版）／false = ATR% 加權（v3 現行 default）

@@ Calc()（:195-197）
       raw[p]=b[0]-50.0;
-      w[p]=W(p,sh);
+      w[p]= W(p,sh);
+      if(InpEqualWeight) w[p]=1.0;   // A 案：等權分支
       if(w[p]>0){ sumW+=w[p]; nW++; }
```

兩行改動就夠，因為 `avgW` 喺等權下必然等於 1.0（全部 `w=1`），
所以下面 `v = raw[p]*(w[p]/avgW)` 自動退化成 `v = raw[p]`——**唔需要再改 XAU 段**，
`gx` 亦自動變成純 `raw` 累加。呢個係源碼結構本身嘅好處，唔使兩處同步改（少一個出錯點）。
