## 二、修法建議：比「`+=` + posId×dealTicket 去重集」更簡單、更穩

你提嘅修法可行，但要去重集 + 跨重啟持久化（現時 CSV 第 1 欄係 `posId`，**冇存 deal ticket**，`grep DEAL_TICKET` = 0）——即係要改 CSV schema 或加額外檔，複雜度上升。

**我建議改用「每輪全量重建」**：

```
SyncTradesFromHistory():
  1. HistorySelect(0, TimeCurrent()+86400)          // 全歷史（已係現況）
  2. 第一趟：掃全部 DEAL_ENTRY_IN，按 posId 記 entry price/time/type/commission（可放細 map 或兩個平行陣列）
  3. 第二趟：掃全部 DEAL_ENTRY_OUT，按 posId 聚合：
        if(posId 未見過) → 新建，lots = dVol, pnl = dProfit ...
        else            → lots += dVol, pnl += dProfit, swap += dSwap, comm += dComm
     並用 entry 資料補 openprice/opentime/type
  4. 用重建結果整批替換 t_* 陣列（t_tradeCount 由重建決定）
  5. SaveTrades()
```

**為咩更穩：**

| | `+=` + 去重集 | 全量重建 |
|---|---|---|
| 跨輪冪等 | 要靠去重集 | **天然冪等**（每次由 history 重算，結果一樣） |
| 跨重啟冪等 | 去重集要持久化（改 CSV 或加檔） | **天然冪等**（無狀態） |
| CSV schema 改動 | 要加 deal ticket 欄 | **唔需要** |
| 多筆 OUT 聚合 | 靠 `+=` + 去重正確 | 靠 `+=` 但每次由零開始，唔會重複 |
| 成本 | O(n) + 去重查詢 | O(n)（兩趟掃，唔係 O(n²)） |
| 順帶解決你 §三-1 講嘅 O(n²) | 未解決（entry deal 仍線性掃） | **一併解決**（第一趟建索引） |

即係：**你 §二 必修 + §三-1 效能問題，同一個改法解決兩個。**

**但決定權係你（code lane）。** 你如果堅持 `+=` + 去重集（例如你想保留「只累加 delta」語義），我接受，只要你喺 v1.60 REPORT 寫明：
