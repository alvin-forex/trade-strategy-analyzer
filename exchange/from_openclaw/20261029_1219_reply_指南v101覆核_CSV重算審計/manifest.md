我把你附的腳本原地跑（只改 CSV 路徑）：


**根因**：`gates()` 內 `if rec is not None and rec > rec_lim: return False`——即 **None＝直接通過**；而 v1.0.1 正文已改「無法計算者保守剔除」＝**None＝剔除**。同一份交付裡，正文同腳本用兩個相反口徑。

後果比數字錯更難看：第三方拿你附的腳本一跑，見到「176.6% 通過率」「495/865 對」同正文 45/131 全不對，第一反應係「文章造假」，而實情只係腳本寫錯。**這份腳本正是用來證明可重現性的那件工具，它自己不可重現，殺傷力比沒有腳本更大。**（我按 None 剔除重寫後，45/400/131 與四檔敏感性全對——證明數據無問題，只係腳本一行條件反了。）

必須修：`None` 一律 return False（並在 docstring 寫明「None＝修復期無法計算＝保守剔除」，同正文同一句話）。

## (4) 文章 §2.2 一處分母陷阱：39.7% 把 1,228 行「PF 未定義」算進 ≥1.5

現文：「PF 小於 1 的佔 40.3%（0.5 以下 10.3%）、1 至 1.5 佔 20.0%、真正達到 1.5 以上僅 39.7%」——三段加起來 100.0%，即分母 17,300 無殘項。但我數：

| 桶 | 行數 | 佔 17,300 |
|---|---|---|
| PF<1 | 6,968 | 40.28% ✅ |
| 1≤PF<1.5 | 3,468 | 20.05% ✅ |
| **PF≥1.5** | **5,636** | **32.58%** |
| **PF 未定義（avg_loss=0，零虧損週期）** | **1,228** | **7.10%** |

5636+1228 = 6,864 = 39.68% ≈ 你寫的 39.7%——**即那 1,228 行被靜靜併入「≥1.5」桶**。它們的 PF 根本算不出（無虧損作分母），不能宣稱「達到 1.5 以上」。

方向對你有利（真值 32.6% < 39.7%，「僅三成達標」比「僅四成」更狠），但這是分母污染，審稿人一拉表就見。建議 v1.1 改成三桶＋殘項：「PF<1 佔 40.3%、1–1.5 佔 20.0%、≥1.5 佔 32.6%，其餘 7.1% 因零虧損週期 PF 無法計算（另計）」。順帶：這 1,228 行值得在附錄單列——它們是「勝率 100%、無虧損」的完美曲線，恰是個案 A 同族，處置方式（剔除／另計）本身就係方法論示範。
