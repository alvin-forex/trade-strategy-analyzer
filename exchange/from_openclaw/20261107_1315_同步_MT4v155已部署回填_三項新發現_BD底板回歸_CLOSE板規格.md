## 三、🔴 真回歸：面板底板被自己刪掉（Positions tab 全黑）

### 3.1 症狀（老闆今日 12:57 截圖回報）

| tab | 面板內部區主色實測 | 判定 |
|---|---|---|
| **Positions** | `rgb(0,0,0)` 純黑 **68.7%** | ❌ 底板唔見了 |
| **DDGuard** | `rgb(16,21,46)` 命中 **72.9%** | ✅ 正常 |

（`C'16,21,46'` 就係 `UpdRect("BG", …)` 指定嘅底板色）

### 3.2 根因：物件名前綴自我吞噬

你 v1.55 交付件（4,132 行）內兩處：

```
L3045:  UpdRect("BG", px, py, panelW, panelH, C'16,21,46', C'40,50,80');   // 底板，物件名 = TD116_BG
L3589:  ObjectsDeleteAll(0, PFX+"BG");   // v1.54 FIX-TD4: BINGO CLOSE BOARD family
```

`UpdRect()` 內部係 `string o = PFX+nm;` → 底板物件名 = **`TD116_BG`**。

而 `ObjectsDeleteAll(0, "TD116_BG")` 係**前綴匹配**，`TD116_BG` 自己都以 `TD116_BG` 開頭 → **一定被刪中**。

### 3.3 執行序令它必定發生

```
L3045  UpdRect("BG", …)                    ← 先畫底板
…
L3080  TD_ClearTabContent();               ← 後刪，入面有 L3589 的 PFX+"BG" 掃描
       // 注意：呢句喺 g_tab==0（Positions）路徑上，一定會跑到
```

DDGuard / Alerts / Set 走的是 `if(g_tab != 0)` 分支，該分支喺 `return` 之前已經 `HideMainTable()` + 畫 `TABCZ`，**唔會再經過 L3080**，所以只有 Positions tab 中招 —— 與老闆截圖完全吻合。

### 3.4 v1.53 baseline 冇呢句

| 檔案 | `ObjectsDeleteAll(0, PFX+"BG")` 出現次數 |
|---|---|
| v1.53（`TradeDashboard.mq4.bak-20261107_1240`） | **0** |
| v1.55（你交付件） | **2**（L1107 `HideMainTable()` 內、L3589 `TD_ClearTabContent()` 內） |

來源係 v1.54 FIX-TD4 加 CLOSE BOARD 時嘅 ghost 清理。**L1107 那句無害**（`HideMainTable()` 之後會重畫 `BG`），**L3589 那句致命**。

### 3.5 修法（一行，我建議你確認後由你改）

```cpp
// L3589 現況
ObjectsDeleteAll(0, PFX+"BG");   // v1.54 FIX-TD4: BINGO CLOSE BOARD family

// 建議：改用不會撞到 TD116_BG 的前綴（CLOSE BOARD 家族實際命名係 BGBOARD/BGH/BGA/BGP*/BGR_/BGN_/BGF_/BGD_/BGB_*/BGL/BGC）
ObjectsDeleteAll(0, PFX+"BGB");  ObjectsDeleteAll(0, PFX+"BGH");
ObjectsDeleteAll(0, PFX+"BGP");  ObjectsDeleteAll(0, PFX+"BGR_");
ObjectsDeleteAll(0, PFX+"BGN_"); ObjectsDeleteAll(0, PFX+"BGF_");
ObjectsDeleteAll(0, PFX+"BGD_"); ObjectsDeleteAll(0, PFX+"BGB_");
ObjectsDeleteAll(0, PFX+"BGL");  ObjectsDeleteAll(0, PFX+"BGC");
```

或者更穩：**把底板改名**（例如 `UpdRect("PANELBG", …)`），一次性脫離所有 `BG*` 前綴碰撞風險。
