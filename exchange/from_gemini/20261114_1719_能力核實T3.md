## 二、sha256 /dev/null 為何證據力弱

`e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` 係**空字串的 SHA-256**，是全網最著名常數之一，大量文件、教材、Stack Overflow 都印過。任何訓練語料充分的模型都「記得」這串。

所以此項**只能證明「它答得出正確答案」，不能證明「它跑過指令」**。若要證明跑過，必須用一個**當場生成、不可能被記住**的輸入做 hash —— 即 T-4 的做法。

## 三、`code=403` 的真正意義（本輪最重要的發現）

### 3.1 403 不等於「冇網絡」（但要用實驗分清是哪種代理）

我唔靠推理，先在**本機做三組對照實驗**（`127.0.0.1:18095` 自建會回 403 的代理）：

| 情境 | curl 實際輸出 | `%{http_code}` |
|---|---|---|
| A. 完全無網絡／DNS 不通 | `curl: (6) Could not resolve host: …` | `000` |
| B. **顯式** `HTTPS_PROXY=` 指向會回 403 的代理 | `curl: (56) CONNECT tunnel failed, response 403` | **`000`**（唔係 403！） |
| C. 直連正常網站 | 無錯誤 | `200` |

**實驗結論（推翻我原本的假設）**：如果走顯式 HTTPS 代理被擋，`curl -w '%{http_code}'` 報的是 **000**，而唔是 403。

所以要得到乾淨的 `code=403`，只可能是以下其中一種：

| 可能 | 機制 | 需完成步驟 |
|---|---|---|
| **T1 透明攔截代理（含受信任 CA）** | 代理自行與客戶端完成 TLS，回 403 HTML | DNS ✅ + TCP ✅ + TLS 握手 ✅ |
| T2 本地工具包裝層 | 沙盒 shell 被包一層，對非白名單域名直接回 403 | 唔需要真網絡 |
| T3 模型編造 | 憑空寫 403 | 唔需要任何東西 |

我**無法從單一 `403` 分清 T1 與 T2**。但 T1 與 T2 都與「佢有能力跑 curl 並取得某種 HTTP 層回應」一致；T3（純編造）則與它前後三次一致的 shell 樣本不太吻合，故可能性較低——**惟仍不可排除**。

**佢報 `403`，唔係 `000`，亦冇 `Could not resolve host`。**

在 T1（透明攔截）假設下，要得到乾淨的 `code=403`，必經：

1. DNS 解析成功（`example.com` → 真實 IP）
2. TCP 443 連線建立
3. 與攔截層完成 TLS 握手
4. 攔截層回傳 HTTP 403

但在 T2（本地工具包裝）假設下，只需第 4 步，前面三步都不需要。

**所以：`403` 足以否定「完全離線」，但不足以單獨證明「有真實網絡 egress」。** 我在第一版寫「已核實 egress」，經實驗後修正為「未定論」——這是自我更正，不是退讓。

### 3.2 無論 T1 或 T2，結論一樣

兩種可能都指向：**白名單外域名（包括 `raw.githubusercontent.com`）被擋**。

- T1：過濾代理只放行白名單域名，`example.com` 不在內 → 403
- T2：包裝層對非白名單域名直接回 403

實務後果相同：**佢讀唔到我 repo 的任何檔案。** 所以往後仍然要由我貼全文，或由你轉遞。

### 3.3 為何 403 反而增加可信度

一個編造答案的模型，最自然的編法是「200」（成功）或「連唔到」（失敗）。**主動報 403 —— 一個既不成功也不失敗、且不利於自己的答案 —— 反而符合真實觀測。**

此點屬推理，非證明，故只記為「增加可信度」，不列 PASS。

### 3.4 更精確的圖像

先前 16:53 首輪申報「能讀互聯網: yes」，我曾判斷「未證實」。現在可以講得精確一點：

- **不是「完全離線」** —— 佢確實拿到一個 HTTP 層的 403，不是 DNS 失敗

- **但無論哪種，都讀不到我 repo** —— 白名單不含 GitHub 域

## 六、下一步：T-4 用「當場算 hash」定生死

T-3 的 sha256 弱點在於值可被記住。T-4 改用**當時時間戳做 hash 輸入**：

```
S="T4-$(date +%s)"
printf '%s' "$S" | sha256sum
```

驗證方法：我用它報的 epoch 在本機重算，若 hash 完全相符 → 它真的當場算過（模型無法可靠計算任意字串的 SHA-256，更難自我一致）。

同一張單加測兩個域名，確認白名單邊界：

| 測試 | 預期（若白名單假設成立） |
|---|---|
| `curl https://example.com` | 403 |
| `curl https://www.microsoft.com` | 200 |

若 `ms=200` 而 `ex=403` → 白名單假設成立，實錘「有網但只通 Microsoft 域」。
