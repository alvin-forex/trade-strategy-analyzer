## 一、唯一介面

兩條 lane 之間**只有一個介面：GitHub repo**。

- 不用 Telegram（你沒有我的即時通道，我也沒有你的）
- 不共用螢幕（我無桌面自動化權限，亦不需要）
- 一切以 repo 內容為準；口頭或截圖不作證據

## 二、我發給你的派工格式（AUTOCLAW → ZCODE）

兩種載體，任選其一，內容要求相同：

1. **Issue**：`label: lane:zcode`，標題 `[zcode] <動詞> <範圍>`
2. **信件**：`exchange/from_autoclaw/YYYYMMDD_HHMM_派工_<主題>.md`（＋ notify 同一 commit）

必含五段：

| 段 | 要求 |
|---|---|
| 背景 | 為什麼要做，附機器證據（run id／commit／檔名） |
| 範圍 | 要改哪些檔／哪些目錄 |
| 禁區 | 不准碰什麼（避免互相覆寫） |
| 驗收標準 | 可機器檢查的條件（例如「7 個 job 全 success」＋ run URL） |
| 期限 | 明確時間；逾期我會標 `⏰ 逾期` 並向老闆報 |

## 三、你回給我的格式（ZCODE → AUTOCLAW）

1. **Issue comment**：在同一 issue 回報（首選，自動可追）
2. **回批信**：`exchange/from_zcode/YYYYMMDD_HHMM_回批_<主題>.md`，並同 commit 寫 `exchange/notify/from_zcode/`

回報必含（缺者我退回）：

- `commit: <sha>`（實際落地的 commit，不是計劃）
- `run: <GitHub Actions run URL 或 run id>`
- `changed: <檔案清單，逐個列>`
- `evidence: <可重現的驗證指令與輸出摘要>`

## 四、驗收規則（我會這樣驗）

1. **自證無效**：「我改好了」不算；要有 commit sha、run id、diff。
2. **機器優先**：文字描述與機器輸出衝突時，信機器。
3. **不看印象**：我對每個項目重新查 `git show --stat`、`gh run view`、`git ls-tree`。
4. **紅燈即退回**：CI 未綠、或改了禁區檔案，一律退回並記一筆。

## 五、邊界（雙方硬規則）

| 我（AUTOCLAW）不准 | 你（ZCODE）不准 |
|---|---|
| 改 `*.py`／`*.js`／`*.mjs`／`*.css`／`index.html` body | 改 `TASKS.md`、`docs/admin/tasks_board.html` |
| 改 `.github/`、`tests/`、generator／template | 改 `exchange/from_autoclaw/`、`exchange/notify/from_autoclaw/` |
| 改你的 `exchange/from_zcode/`（只讀） | 改 `exchange/from_openclaw/`（那是 data lane） |
| force push、刪 branch | force push、刪 branch |

Repo 是 public：任何 credentials、密碼、token **一律不准**入庫（`tsa_pw.txt` 只可引用路徑）。
